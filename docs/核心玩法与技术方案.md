# 核心玩法、主题方向与 3D 技术方案

> 2026-11-09 草案。市场数据见 [市场调研-2026-11.md](市场调研-2026-11.md)。技术部分参考 Swarm Orbit（`D:\jump`）的 `docs/design/tech.md`、`docs/platform.md`、`docs/design/art.md`。

## 1. 从暴力摩托里拿什么

只拿玩法骨架，不拿名字、人物、美术、音乐、赛道。

### 1.1 核心循环（拆成 5 个可复用的机制）

| # | 机制 | 原作里的样子 | 我们要保留的本质 |
|---|---|---|---|
| A | **边跑边打** | 并排时出拳、踢、挥棍，把对手打下车 | 竞速中途可以"处理掉"对手，名次不只靠速度 |
| B | **抢武器** | 打掉对手手里的棍子就归自己 | 战斗中有临时掉落，打赢一次后下一次更强 |
| C | **摔车代价** | 撞车或被打下车后人飞出去，跑回车上 | 失误有明显、好笑、但不致命的代价（丢几秒和名次） |
| D | **路上的麻烦** | 车流、对向车、动物、警察追捕 | 赛道本身在制造风险，躲障碍和打架抢同一个注意力 |
| E | **奖金换装备** | 名次给钱，买更快的车；车损太重或被抓要付钱 | 每局之间有成长，局内表现决定成长速度 |

另外两个原作特征，网页版**不照搬**：

- 14 人长赛道（一局 3–5 分钟）：太长。改成 60–120 秒一段，6–8 个对手。
- 键盘组合键战斗：手机上做不了。改成单指操作，见 1.3。

### 1.2 一局的节奏（目标 120–180 秒）

```
起跑 5s → 车流段 25s → 第一次并排冲突 → 捡武器 → 障碍段 → 警察/追兵出现 → 冲线 → 结算
                         ↑ 每 8–12 秒一次"可打的人在旁边"
```

- 平均游玩时长目标仍是 10 分钟（Playgama 指标）。靠"再来一局"堆起来：一局 120–180 秒（2026-11-09 从 90 秒改），结算 10 秒，升级 15 秒，大约 3–4 局。
- Swarm Orbit 的教训：真实中位数只有约 90 秒，大部分人在第 3 波前就走了。所以**第一局的前 20 秒必须已经打到人、摔过一次车**，不能先教 30 秒操作。

### 1.3 操作（单指，竖横屏通用）

| 输入 | 动作 |
|---|---|
| 自动油门 | 不需要按加速（超休闲门户的默认做法） |
| 左右拖动 / 左右键 | 换道或转向 |
| 点击（对手在旁边时） | 朝有人的那一侧出手；两侧都有人就打近的那个 |
| 向下滑 / ↓ | 刹车，躲警察或让对手先过去 |
| 长按（可选，后期解锁） | 蓄力重击 |

- 攻击判定做"宽容"：对手进入侧面范围时高亮，点任意处就打。不让玩家精确瞄准。
- **出手有代价**（2026-11-09）：每次出手自己掉 10% 速度（`ATTACK.selfSlow` 0.9），打中对方掉 14%（`ATTACK.slow` 0.86）。打中净赚一点，打空纯亏，所以不能见人就打。
- 不用 Esc 暂停，暂停键是 P，暂停按钮从第一帧就画出来（Swarm Orbit 和 Tidehook 的教训）。

### 1.4 成长线

- **车/坐骑**：速度、操控、耐久三条属性，用奖金升级。
- **武器槽**：开局可选一件带进场的武器（棍、链、平底锅之类，视主题而定），局内捡到的只用到本局结束。
- **对手档案**：6–8 个固定对手，有名字和性格。被同一个人打下车 3 次会弹出"仇人"标记，打回去给额外奖金。原作玩家最记得的就是这个，成本低。
- **激励广告位**：结算奖金 ×2；摔车后立刻回到车上（跳过跑回去）。插屏只在两局之间。

3. **警察追逐**
   - Blacktop Police Chase：Poki 汽车类增长最快，美国 450 万

**最重要的一条：这个玩法已经有人做了。** **Smash Speed!**（JoyBits，2026-06-05 上线）：

- Playables 上 5 个月 1100 万播放，已经上了 CrazyGames。
- 玩法是骑摩托穿车流、撞翻对手（对手头上的数字比你小就能撞翻）、打 Boss 卡车、升级车。
- 这几乎就是暴力摩托的骨架。

这说明需求被验证了，但只做"摩托 + 撞人 + 升级"会和它正面撞。差异化要靠：

- 主题
- **近身出手**（不是比数字撞）
- 摔车布娃娃的笑点
- 仇人系统

**上升中**（近 90 天上线）：

- **身边的人搞笑**：Annoying Uncle Punch Game 47 天 2400 万（每天约 51 万），Teacher Life 950 万
- **怪载具**：Shift Shapes Car 2 个月 1800 万（每天约 35 万）
- **obby**：10–11 月新上 14 款，最好的只有 280 万
- **brainrot / "67"**：上新量大，但没有一款进前 50

**平台方面：**

- Poki 汽车类占美国播放 10%，前 5 名拿走近 40%；平均时长最长的是 Smash Karts（573 秒，竞速 + 道具对战）。
- CrazyGames 首页有"Meme & bloxy"合集。

### 2.2 美术和方向

- Playables 前 50 约 80% 是**低多边形风格化 3D**（超休闲手游移植），角色多为无脸假人或卡通人物。前 50 里没见到像素风和体素风。
- 竞速类分两派：低多边形（Race Master、Turbo Stars）和半写实车（Racing Limits、Traffic Racer 3D）。
- **方向是硬性要求**：
  - YouTube 禁止锁方向，所有比例都要能玩。
  - Playgama 要求竖屏 + 适配好的横屏，不能有黑边。
  - CrazyGames 不收横屏带黑边的手游移植。
  - 所以第 3.6 节的车后追尾镜头、两种方向各调一套，是必须做的，不是加分项。
- **我们的优势**：Swarm Orbit 已经验证了"代码生成模型 + 顶点色"的路线（不用 PBR、不像 AI 图）。Playgama 拒收全 AI 生成的游戏，并说 AI 画面的游戏数据差一倍以上；YouTube 也要求不能看起来像 AI 做的。

### 2.4 推荐：1 为主题，4 的怪载具做成长线，3 做局内压力

**主题定为碰撞测试假人。** 理由：

1. **和核心玩法天然一致**："被打下车 → 飞出去"本来就是碰撞测试的主题，摔车从惩罚变成笑点（机制 C）。
2. **踩在两个大类的交集上**：无脸假人是 Playables 前 50 的主流角色，撞车/布娃娃是竞速类最大的子类。
3. **合规最干净**：没有血、没有真人、没有 IP；13+ 全年龄，YouTube 和 Poki 都过。
4. **美术最便宜**：假人就是几段圆柱和球，代码就能拼出来，正好走 Swarm Orbit 的代码建模 + 顶点色路线。布娃娃也就是 5–7 个节点（第 3.3 节）。
5. **和 Smash Speed 拉开**：
   - 它是写实摩托 + 比数字撞人，我们是假人 + 近身扇 + 飞出去的布娃娃。
   - 缩略图一眼能分开：假人在半空中，对手的拳头还在画面里。

**从 4 拿来"怪载具"做成长线**（Shift Shapes Car、Scooter Xtreme 证明载具新奇感能卖）：

- 起步：试验场滑板车
- 解锁：购物车 → 办公椅 → 老年代步车 → 马桶火箭 → ……
- 每种载具手感不同（速度/操控/耐久三条属性的不同取舍），也是皮肤付费点。

**从 3 拿来"警察"做局内压力（机制 D）：**

- 试验场的安保车会追上来挡在你前面，或者并排把你往护栏挤、让你掉速，但从不撞你（见 3.3.3）。
- 反向模式“你当保安抓逃跑假人”已经做成支线“保安班”，见 3.3.14。

**5（骑士）留作节日活动皮肤**：假人穿盔甲骑木马，成本只是换装。

| 项 | 方案 |
|---|---|
| 场景 | 一条贯穿多个"测试场"的公路：试验跑道 → 城市街道 → 高速 → 工地 → 机场跑道。每段换配色和路边景物，不换玩法 |

## 3. 3D 技术方案（照搬 Swarm Orbit 的架构）

### 3.1 技术栈

| 项 | 选择 | 理由 |
|---|---|---|
| 渲染 | Three.js（跟 Swarm Orbit 同版本，r186） | 已有完整的加载、预热、分档经验 |
| 语言/构建 | TypeScript strict + Vite，`base: './'` | 同上 |
| 模拟 | 30 Hz 固定步长，和渲染分开；无头 bot 可跑 | 用 bot 调每局时长、名次分布、经济曲线 |
| 平台 | `Platform` 接口：playgama / stub / offline，后面加 youtube、crazygames | Bridge 失败或 10 s 没初始化完就走 offline |
| 资源 | glTF + Draco，单独文件不内联 | Swarm Orbit 把 GLB 拆出来后主包 gzip 512 → 253 KB |
| 包体 | 首包 gzip ≤ 5 MB，`npm run package` 超了直接失败 | Poki 首包 8 MB、YouTube 30 MB，5 MB 三边都过 |

### 3.2 加载

照抄 Swarm Orbit 的 `boot.ts` 流程：

1. `index.html` 内联启动画面（深色底 + 进度条），第一个字节就有东西看。
2. SDK 初始化和游戏 chunk + GLB 的流式下载**并行**，按真实字节显示 8% → 90%，大小在构建时由 `bootSizes` 插件写进去。
3. `import('./main')` 不等 `initialize()`。第一帧画完后淡出 0.35 s，再发 `gameReady`。
4. Bridge 的 script 标签放在 `</body>` 前，不放 `<head>` 第一位（会白屏）。
5. iframe 为 0×0 时不初始化，等 resize。
6. WebGL context lost 时显示 ↻ 按钮。

### 3.3 竞速游戏特有的渲染问题

Swarm Orbit 是固定场地，这里是一直往前跑的路，多出几件事：

| 问题 | 做法 |
|---|---|
| 无限长的路 | 路面按段（chunk）生成，样条曲线 + 起伏；身后的段回收进对象池，不新建 |
| 视距 | 雾 + 远处低模，视距 150–250 m；雾色就是天空色，不用天空盒贴图 |
| 车流和对手 | 每种车一个 `InstancedMesh`（Swarm Orbit 的虫子就是这么做的）；轮子转动、受击闪白放进 instance 属性和顶点着色器 |
| 路边景物 | 按种类合并成 InstancedMesh，静态的用 `flatten.ts` 合批（Swarm Orbit 火车 53 → 22 次绘制） |
| 摔车飞人 | **只在视图层**做简化布娃娃：12 个点的 Verlet（头、双肩、骨盆、肘、手、膝、脚），不上物理引擎。模拟层只记"摔了、落点、几秒后归位"，保证 bot 可跑、可复现 |
| 速度感 | FOV 随速度变大、路边速度线、镜头轻微抖动；这些都便宜，比加模型细节划算 |
| 打击感 | 命中停顿 2–3 帧、受击闪白、数字飘字用字形图集 1 次绘制（Swarm Orbit 的做法） |

### 3.3.1 美术管线：代码建模 + 顶点色 + 卡通着色 + 描边（2026-11-09 第一版）

全部模型在代码里用圆角盒、胶囊、球、圆柱拼出来，不用贴图、不用模型文件、不用 AI 生成。代码在 `src/view/toon.ts`。

- **`Kit`**：把一个物体的零件（几何体 + 颜色 + 位置）合并成**一个几何体**，颜色写进顶点。一辆车、一条胳膊各是 1 次绘制。
- **着色**：`MeshToonMaterial`，3 档明暗的渐变图（`NearestFilter`），全游戏共用 1 个材质。
- **描边**：反向外壳（inverted hull），**烘进同一个几何体**：每个零件再复制一份，沿平滑后的法线外推 2.4–4.5 cm，翻转绕序，涂深色。不加后处理，不多一次绘制，代价是三角面翻倍。贴纸、灯、小零件不描边。
- **车的颜色**：每种车型一个 `InstancedMesh`。车身零件带 `paint=1` 顶点属性，着色器里只让实例颜色染车身，玻璃、轮胎、描边不变色。
- **车型由 `car.id` 哈希决定**，只在视图层。模拟层不知道车型，碰撞框仍是 1.9 × 4.4 m，所以五种车都要装进这个框里。金哈希不变。
- **假人**：每个骑手 5 次绘制（滑板车、腿 + 骨盆、躯干 + 头、左右胳膊），各自一个材质，`emissive` 做受击闪白。布娃娃用同一个材质，也带描边和头部贴纸。
- **测试贴纸**做成几何体：4 个黑黄相间的四分之一圆 + 黑边，不用透明贴图。

| 物体 | 三角面（含描边） |
|---|---|
| 骑手（人 + 车 + 武器外） | 约 4.9k |
| 车（5 种） | 2.3k–3.1k |
| 布娃娃 | 约 0.6k |
| 巡逻车 | 约 1.6k |

**实测**（1280×720，10 个骑手，比赛中）：29–51 次绘制，128–150k 三角面。改之前是 34 次、86k。手机预算按 100 次绘制、200–300k 三角面算，还有余量。

- **大头在赛道本身**：整条地面、护栏、树是全程的大网格，不做视锥剔除（地面约 26k、树约 15k、护栏约 14k）。要省就先按段切开。
- **`?stats`**：左下角显示帧率、最慢一帧、绘制次数、三角面、几何体和着色器程序数。在手机上调美术时用。

**还没做的**：还没在真手机上测帧率。路边景物在 3.3.14 里换成了卡通着色。

### 3.3.2 打击感、布娃娃和安保车避让（2026-11-09）

**出手动作**（`src/view/rider.ts`）：0.42 秒分三段。前 0.2 秒蓄力（胳膊往后拉、上身扭过去），0.2–0.36 秒甩出去（上身反扭、往前探），然后缓回原位。模拟层在出手后第 4 帧（约 0.13 秒）判定命中，正好落在甩出去那一段。甩的时候身后带一道白色扇形拖影，左右出手用 `scale.x = side` 镜像。

**被打中**：
- 身体往挨打的方向倒（`lean.rotation.z` 上的弹簧，k=170、阻尼 11），KO 倒得更多。
- 上身压扁再弹回（squash & stretch），受击闪白。
- 命中点冒一个朝镜头的漫画爆炸星（`fx.pow`）：黑边 + 黄色（KO 是橙红）+ 白芯，先放大到 1.3 倍再缩回、旋转、0.3 秒淡出。6 个循环复用，不做深度测试。

**布娃娃**（`src/view/ragdoll.ts`）：
- 12 个点，棍子分两种：一种保持长度，一种只限最短距离（当关节限位，防止胳膊腿折进身体）。
- 躯干朝向由双肩和骨盆算出，头跟躯干走；四肢各一段几何体，从肩/髋接出去。
- 甩出去时给整个身体一个角速度（`ω × r`），所以会翻跟头而不是平移。力度看怎么摔的：被车撞 1.45，被打下车 1。
- 头、肩、骨盆砸地速度超过 4 m/s 时冒一团灰（`fx.puff`），0.18 秒内最多一次。

**安保车避让**（模拟层，`World.patrolTraffic`）：
- 原来安保车只管追人，直接从车流里穿过去。现在对每个横向位置算"多久会撞上最近一辆车"；要去的位置不到 1.4 秒就会撞，就换一个分数最高的车道（`min(净空时间, 4) - 偏离距离 × 0.1`，逆行车道扣分）。
- 旁边有车时不横移进去；同向前车太近就限速跟车。车流看到前方 10 m 内同道有安保车也会减速。
- 测试 `src/sim/patrol.test.ts`：8 局 bot 比赛，安保车和车重叠的帧数必须为 0（改之前是 1230 帧）。
- 这是模拟层改动，`SIM_VERSION` 升到 3，金哈希更新。

### 3.3.3 警车只挡不撞，暴徒和对手一样打（2026-11-09，SIM_VERSION 5）

试玩反馈：警车和暴徒对玩家的伤害太明显，让人反感。第一版（SIM_VERSION 4）只是把数值调软（被抓不下车、罚款减半、暴徒少出手），方向不对。改成：

**警车：挡路或挤你，但从不撞你**（`World.updatePatrol` / `patrolContacts`）
- 从后面上来时走相邻车道，不往玩家背上顶。离玩家 13 m 时响警笛，轮流用两招：
  - **挡路**（block）：从旁边超到你前面 6 m，切进你的线，按你极速的 80% 开。你要变道绕过去，或者跟在后面吃亏。
  - **挤压**（squeeze）：和你并排，往你这边压。贴着它会摩擦掉速（每帧保留 99.3%），被压到护栏上再额外掉速（每帧 99%），实测 3 秒内从 30 m/s 掉到 20 m/s。刹车或者变道就能脱身。
- 每招最多 4 秒（SIM_VERSION 6 起），然后让开你的线、刹车退出比赛。见 3.3.4。
- 警车是实心的：骑手在它旁边会被推开（同手动挤压一样冒火花），在它后面会被挡住，在它前面它会刹车。接触面用上一帧的相对位置判断，不会中途翻转。
- 没有罚款、没有"被抓"、不会因为警车摔车（`CrashCause` 里去掉了 `'patrol'`）。
- 横移时按"这一帧走完后的位置"检查车流，不会贴着慢车尾巴切进去；后面有车追上来时自己加速，不让车顶进车里。

**暴徒：就是带家伙的对手**（`thugThink`）
- 出手概率和普通对手一样（`激进度 0.9 × AI.swingAtPlayer`），血量一样（3）。
- 一定带武器：前半程平底锅，过了 50% 赛程领头的那个拿棒球棍。
- 你可以反击；打下车后它的武器掉在路上，可以捡。
- 追杀者的出手倍率、领跑威胁间隔恢复到原来（2.5 倍；11 s → 5 s）。保留"玩家摔车后 10 s 不来新威胁"。

**实测**（24 局，bot 速度和操控各升 3 级，代表能领跑的玩家，不主动找架打）：

| 每局 | 数值 |
|---|---|
| 完赛时间：有警车 / 没有警车 | 152 s / 152 s（警车只是麻烦，不吃时间——bot 不会躲，真人会更灵活） |
| 被暴徒打中 / 打下车 | 1.2 / 0.8 |
| 你打中暴徒 / 打下暴徒 | 3.4 / 1.0 |
| 平均名次 | 2.1 |

测试 `src/sim/patrol.test.ts`：警车和车重叠帧数为 0；任何骑手每帧结束时都不在警车里面；挤压时玩家平均每帧净掉速超过 0.05 m/s。

### 3.3.4 每辆警车只来一次（2026-11-09，SIM_VERSION 6）

试玩反馈：一辆警车老跟着我。可以多几辆，但不能一辆一直跟。

现在同一时间路上最多一辆警车，但每辆只出一招，出完就走（`World.updatePatrol` / `sendPatrol`，状态 `chase | lurk | block | squeeze | leave`）：
- **出场**：赛程 25% 之后开始；终点前 300 m 不再来新的。轮流三种来法：
  - 第 1、4、7 辆：从后面 55 m（镜头外）追上来，挤你。
  - 第 2、5 辆：在前方 150 m 的同向侧车道（车道 1 或 3）慢慢开，速度是你的 45%；出场时挑一个附近没车的位置，挑不到就过 1 秒再试。你追到它后面 40 m 时响警笛，横切到你前面挡路。
  - 第 3、6 辆：从后面追上来，挡路。
- **出招**：挡路或挤压各最多 4 秒（挡路的计时从它真正挡在你前面才开始）。
- **离开**（leave）：先让开你的线，然后比你慢 15 m/s，落到你身后 30 m（镜头外）或者超出你 200 m 时消失。你冲线时它也马上离开。
- **下一辆**：上一辆消失后过 12 s 来下一辆（赛程越往后越短，终点附近 7 s）。
- 你摔车时，正在追的车停在你身后 30 m 等你骑起来；正在出招的车直接离开。追了 20 s 还没追上的车也离开。

**实测**（60 局，bot 速度和操控各升 3 级，不主动找架打）：

| 每局 | 数值 |
|---|---|
| 来的警车 / 真正出招的 | 4.5 / 4.4 |
| 单辆警车在路上最长 | 33 s（大部分时间在镜头外追） |
| 完赛时间：有警车 / 没有警车 | 157 s / 156 s |
| 平均名次：有警车 / 没有警车 | 2.2 / 2.4（差别在噪声范围内） |

测试 `src/sim/patrol.test.ts` 新增一条：同一辆车不会响第二次警笛；每局至少 3 辆；单辆在路上不超过 40 s。

### 3.3.5 警车随机化（2026-11-09，SIM_VERSION 7）

试玩反馈：警车能随机一些吗——数量、时间、出现方式都随机。

3.3.4 的规则不变（同一时间最多一辆，每辆只出一招就走），但固定轮换改成按局、按车掷骰子。警车用自己的随机流 `patrolRng = seed*17+11`，不影响车流和对手 AI。区间都写在 `C.PATROL` 里，格式是 `[最小, 最大]`。

- **数量**：每局 2–6 辆（`count`）。
- **第一辆什么时候来**：赛程 12%–40%（`startAt`）。车多的局来得早，再加一点抖动。
- **间隔**：基础间隔还是 12 s 到 7 s，再乘两个系数：
  - 车多的局乘 0.35，车少的局乘 1.7（`busyGap`）。
  - 每次再乘 0.3–1.8 的随机数（`gapJitter`）。
  - 另有 20% 的概率下一辆 1.5–4 s 后就来，紧跟着上一辆（`pairChance` / `pairGap`）。
- **来法**：每辆从四种方案里随机挑一种，不和上一辆重复。
  - 后面追上来挡路
  - 后面追上来挤压
  - 前方等着，横切挡路
  - 前方等着，你到它旁边时贴过来挤压
- **每辆自己的参数**：
  - 从后面出场的距离 45–70 m
  - 在前方等待的距离 120–190 m
  - 等待时的车速是你极速的 35%–55%
  - 横切时机：你追到它身后 25–45 m 时
  - 挡路时在你前方 5–8 m
  - 出招时长 2.5–5 s
- **离开**：
  - 在你前面时加速开走，超出你 45 m 就消失。
  - 在你后面时减速，落后 30 m 消失。
  - 在你身边被车流卡住超过 5 s（你也被它挡着），就直接下道消失。
- **车流修正**：警车在车流里留的前后余量加到 0.8 m，抵消"车流先动、警车后动"那一帧的位移。另外，后面来车逼它加速时，不会让它顶到前面那辆车。

**实测**（60 局，同上的 bot）：

| 每局 | 数值 |
|---|---|
| 警车数 | 2 辆 14 局，3 辆 11 局，4 辆 15 局，5 辆 9 局，6 辆 11 局 |
| 第一辆出现 | 第 19–73 s |
| 四种来法 | 各约 1/4 |
| 单辆警车在路上最长 | 33 s |
| 完赛时间：有警车 / 没有警车 | 160 s / 156 s |
| 平均名次：有警车 / 没有警车 | 2.9 / 2.4 |

### 3.3.6 摔车后车滑出去，人跑回车上（2026-11-09，SIM_VERSION 8）

试玩讨论：摔倒后加一个跑向自己车的过程。这也让广告位"摔车后立刻回到车上（跳过跑回去）"有了实际内容。

**模拟层**（数值在 `C.DOWN`）：

- 摔车时人和车分开。
  - 人以 20 m/s² 减速，躺够 30 tick（被打下车）或 40 tick（撞车）。
  - 车以 11 m/s² 减速，所以车总比人滑得远，越快越远。车只吃 60% 的横向推力。
- 人停稳后起身，跑向车：
  - 0.25 s 内提速到 8 m/s，横向按 0.7 倍速度挪（v16 起改成 0.4 s、5 m/s，最多跑 6 s，见 3.3.13）。
  - 离车 1 m 内就回到车上，位置换成车的位置。
  - 最多跑 4 s，超时也放回车上。
- 暴徒摔车还是直接退场，不跑。
- `Rider` 新增 `bikeX/bikeZ`（和上一帧的 `bikePX/bikePZ`）、`bikeV/bikeVx`、`runT`。`runT > 0` 表示正在跑。
- 测试 `src/sim/down.test.ts`（种子 1–6）检查：
  - 八成以上的摔车有跑回去的阶段。
  - 躺着时车不会在人身后。
  - 回到车上时就在车的位置。
  - 倒地最长不超过 `maxRun + 1` 秒（v21 起是 `maxRun + stand + 1`）。

**视图层**：

- 倒地时 `RiderView` 只画躺倒的滑板车，放在车的插值位置。车向摔出去那一侧转约 50°。
- 布娃娃的落点和模拟层的人不一致，常差几米。
  - 所以跑步从布娃娃实际停下的位置开始，朝车跑。
  - 进度跟模拟层同步：用模拟层的人离车的剩余距离折算。这样两边在同一 tick 到车上，回车时不会瞬移。
- 起身用 0.35 s 从躺姿混到跑步姿态（v21 起先花 1.7 s 慢慢爬起来、做个搞笑动作，见 3.3.19）。跑步是程序动画：腿和手臂交替摆、身体上下颠、上身前倾，面朝车。
- 跑的时候物理停掉，`hide()` 后下次摔车重新开始。

**实测**（40 局，同上的 bot）：

| | 改之前 | 改之后 |
|---|---|---|
| 每次倒地时间 | 2.0–2.4 s，平均 2.22 s | 1.0–3.8 s，平均 2.27 s |
| 其中跑回去 | — | 平均 1.07 s，最长 2.4 s |
| 车和人拉开的距离 | — | 平均 5.0 m，最远 9.5 m |

倒地总时长基本不变，但快速撞车的代价变大，轻碰变小。完赛时间 161 s → 155 s，平均名次 3.0 → 2.35。倒地时长几乎没变，这个差距多半是因为规则一改，同一个种子跑出来就是另一局；40 局的噪声不小，不要当成变容易了的结论。

**广告位接口（还没做）**："立刻回到车上"要做成一个输入：玩家点了广告且看完后，下一个 tick 在模拟层直接调 `recover()`。这会改变一局的结果，所以必须进回放：`InputRow` 要加一列（或加一种事件行），同时升 `SIM_VERSION`。等接激励广告时再做，现在不预留。

### 3.3.7 警车逼停：往路肩挤你，在前面拦你（2026-11-09，SIM_VERSION 9）

试玩反馈：警车追上来以后没有往旁边挤我。警察是要我停车的，所以应该把我往边上挤；在前面拦我也一样。我要自己看车流想办法躲过去。

原因：
- 旧的挤压在追上来时就往里压，结果顶在玩家车尾，被挡住了，根本没并排。
- 4 秒计时从响警笛就开始算，真正贴上的时间很短。

现在每辆警车的目的都是逼你靠边停车（`World.updatePatrol`，数值在 `C.PATROL`）。

**挤压（squeeze）：并排后往路肩推**
- 从后面来的警车一律挤压（方案只剩 `behind squeeze / ahead block / ahead squeeze` 三种）。
- 接近时走你左边隔一条车道，不往车尾上顶。你在逆向车道（x < -3.5）时才走右边。
- 和你齐头（前后差不到半个车长）后，才开始往里压。
  - 压的方向是远离它自己的那一侧（`push`），通常是右边的路肩。
  - 横移速度 6 m/s（`pushSteer`）。
  - 贴着你时摩擦掉速，每帧保留 99%（`rub`，原来是 99.3%）。
- **不把你推进车里**（`carOnShoulder`）：被推的那一侧 0.3–5 m 内有车，就退开 1 m，给你留出空隙。车要么在你旁边，要么 1.4 s 内会追上（`carWarn`）。
  - 所以脱身的办法是车流：贴着路肩那侧的车走，它就不敢压。从车缝里钻过去，它太宽，跟不过来。
- 计时（`hold`）只算真正贴上的帧数。出招时间到了就离开；另外有兜底：出招时间再过 6 s（`pressMax`）还贴不上，也会走。

**挡路（block）：在前面拦你，越开越慢**
- 切到你前面后跟着你的线横移，速度 8.5 m/s（`blockSteer`）。操控升满的骑手能甩开它。
- 车速从你极速的 80% 降到 55%（`blockPace`），在出招时间内逐渐降下来。
- 计时只算它真的在你前面 12 m 以内的帧。被你超过 2 m 就放弃。

**实测**（40 局，bot 速度和操控各升 3 级。bot 不会主动利用车流脱身）：

| 每局 | 有警车 | 没有警车 |
|---|---|---|
| 完赛时间 | 157.7 s | 152.7 s |
| 平均名次 | 3.08 | 2.15 |
| 摔车次数 | 8.5 | 8.1 |

- 挤压时平均贴上约 13 次。推向右侧路肩 22 次，推向左侧 6 次。车速最多从 30 m/s 被挤到 14 m/s。
- 有一部分撞车发生在挤压期间，逐帧查过：
  - 都是 bot 自己转向撞上的车。当时警车要么还没贴上来，要么已经因为路肩有车退开了。
  - 没有一次是警车把人推进车里。

测试：`src/sim/patrol.test.ts` 不变，仍然通过：
- 挤压时玩家平均每帧净掉速超过 0.05 m/s。
- 警车和车不重叠。

`src/sim/down.test.ts` 放宽了一处：回到车上那一帧如果正好被挤，位置可能差 0.5 m。

### 3.3.8 AI 像人在开车：反应延迟、横向惯性、意图（2026-11-09，SIM_VERSION 10）

试玩反馈：AI 太简单。
- 警车挤我时我已经停车了，它还盯着我。
- 警车拦我时和我完全同步变道。对手也一样，完全复制我的变道方向。

原因：所有 AI 每帧直接读玩家当前的位置，横向又是匀速瞬时转向，所以玩家一动它们同一帧就跟着动。

**共用的一层（`World.seen`、`World.move`，数值在 `C.AI`）**
- **反应延迟**：每个骑手和警车都记着别人最近 24 帧的位置（`hx/hz/hv` 环形缓冲，`remember()` 每帧末尾写入）。
  - AI 看到的是 `react` 帧之前的样子，再按速度和一半的横向速度往前推一点（`predict` = 0.5）。
  - 对手的 `react` 按警觉度在 6–15 帧之间，每局再随机加 0–2 帧。警车 8–14 帧。
  - 所以急刹、急转要过一个反应时间才被看到；假动作会把它们往错的方向带。
- **横向惯性**：AI 不再瞬间对准目标线，而是要把横向速度加起来、再减下去（对手 13–22 m/s²，按警觉度；警车 11 m/s²）。
- **意图要坚持**：对手每 0.8–1.8 s 才重新想一次要干什么；绕车时选的线保持 0.7 s（`escHold`）。

**警车（`World.updatePatrol`）**
- **停车就放行**：挤压或拦截时，它看到你的车速低于 9 m/s 持续 0.4 s，就转入 `halt`。
  - 开到你前面隔一条车道停住，1 s 后弹出 `WARNING! MOVE ALONG` 并离开（事件 `patrolLetGo`）。
  - 你中途又加速走了（超过 14 m/s），它就回到原来的挤压或拦截。
- **挤压**：急刹会让它冲过头（看到的位置是旧的）。冲过头后，拦截时间还没用完就转成在前面拦你，否则离开。
  - 车身贴着你时它能"感觉"到你，反应只延迟 3 帧（`feel`），所以贴住以后不会一刹就甩掉。
- **有真实的极速**：每辆车在 33–38 m/s 之间随机。被甩开 80 m 就放弃（`outrun`）。速度升满的玩家能甩掉慢的那几辆。
- **按车道拦**：拦截时它守的是一条车道，不是你的每一次抖动。
  - 你越过车道线 0.3 m 以上（`laneCommit`）它才换道，换完至少守 12 帧（`laneHold`）。
  - 换道只按它真看到的位置判断，不做预测，所以一定比你晚一个反应时间。
  - 在车道内最多往你那侧偏 0.6 m（`laneShade`）。
  - 结果：真变道它晚半拍才跟上；假动作（晃出去马上回来）会把它骗到旁边车道停一会儿。
- 加了惯性以后它躲车变慢了，所以：
  - 躲车时打方向更猛（横向加速度 ×1.8），提前 2 s 看车（`dodgeT`，原来 1.4 s）。
  - 已经和车并排时，往远离那辆车的方向移动总是允许的。
  - 从后面刷出来时不在逆向车道。离开时如果要走到逆向车道一侧，就改走另一侧。
  - 刷新车流时不会把车刷在警车身上。

**对手（`rivalThink`，数值在 `C.AI`）**
- 三种意图：`race`（按车道跑、绕慢车、偶尔换道）、`harass`（盯上某人）、`back`（只剩 1 点血又挨了打，退开 2 s）。
- **盯人时选定一侧就不换**（`foeSide`），离你 1.2–1.65 m 再加武器距离的 0.6 倍。在这个距离上随机晃动 ±0.35 m（`wander`），不会死贴，也不会镜像你的变道。
- **性格**：盯玩家的概率是每次重新思考 1.1 × 攻击性（14 m 内），盯别的对手是 0.12 × 攻击性（10 m 内）。盯 4–7 s（再乘 0.6 + 攻击性），之后歇 2–4 s。
- **记仇**：上一个打中它的人（`hitBy`）被盯上的概率翻倍。
- **挥棒时机**：对方和它齐头、且刚挥过棒（有空档）时更愿意出手（×1.8）。还没对齐时减半，退开时只有 0.3。
- 追领先者（hunt）时不受极速上限限制，能追得上。橡皮筋略微加强：落后时最多 +20%（原来 +16%）。

**暴徒（`thugThink`、`startAmbush`）**
- 两个一组时分工：
  - 50% 是**钳形**，左右各一个。
  - 否则一个**主攻**，另一个**拦路**：在你前面 3.5 m、按你车道（同样有换道门槛和最短守道时间）、以你 92% 的速度骑，让你骑进战斗里。和你齐头了，或者出招时间过半，就转为主攻。
- 侧向距离按武器长短定。快被打下车时也会先退开，再回来打。

### 3.3.9 打进车流、预警和反击、抢武器、通缉等级、罚款（2026-11-09，SIM_VERSION 11）

**一局时长**：目标从 90 秒改为 **120–180 秒**（2026-11-09 试玩后决定，现在的节奏是对的）。实测竞速 bot 146 s，打架 bot 174 s，都在范围内。

**第一次交手**：设计要求前 20 秒内打到人。实测（40 局，`_first.ts`，已删）第一次交手的中位数是起跑后 3.5 s，已经满足，不用改。

**打进车流 / 撞墙（`SHOVE`、`SHOVE_BONUS`）**
- 被打中的人会被推向侧面：推力 = 基础 5.5 + 武器推力（平底锅 +1，球棒 +2）。
- 硬直 `stagT` 期间不能转向（玩家 3 帧，AI 6 帧）。横向速度每帧保留 0.88（平时 0.82），所以会被一路带过去。
- 被打后 24 帧内（`shoveT`）：
  - 撞上车：照常摔车，算到打人的人头上。
  - 撞上路边护栏，且横向速度朝外超过 1 m/s：摔车，原因 `wall`。
- 玩家这样把人打下去：+$100（`SHOVE_BONUS`）、慢镜头、`INTO TRAFFIC!` / `INTO THE WALL!`。如果是仇人，同时算报仇。
- 球棒或平底锅能把外侧车道的人打上护栏；空手只能把已经贴着护栏的人打上去。路中间挨一下只会偏离路线。

**预警和闪避反击（`ATTACK.windupAI`、`dodgeX/dodgeZ`、`open`、`counterDmg`）**
- AI 出手要蓄力 10 帧（0.33 s），玩家仍是 4 帧。
- 蓄力期间有三种提示：
  - 动作：举高、往后拉、发抖。
  - 名字牌：变红闪烁。
  - 屏幕边缘：来袭方向出现红色 ⚠，并有提示音。
- 出手时按目标蓄力开始时的位置和速度外推。目标实际偏离外推位置横向超过 1 m 或纵向超过 0.8 m，就算闪开：`DODGED!`，不会误伤旁边的人。
- 打空的 AI 露出破绽 24 帧：减速 6%，不能出手，名字牌变黄 💥。
- 这时玩家打中它就是反击（`COUNTER!`）：伤害 +1，必定打掉它的武器。

**抢武器（`STEAL`）**
- 打中拿武器的人时有概率打掉：玩家打 35%，AI 打 15%，反击必定打掉。
- 打人的一方空手、且不是暴徒：直接抢到手（`STOLE A BAT!`）。否则武器掉在前方 6 m 成为可捡道具。

**通缉等级（`HEAT`，0–3 星，HUD 顶栏）**
- 警车在 30 m 内时，玩家每打中一次 +0.15，KO 再 +0.4。
- 把人打进车流或撞墙也加热度。
- 警车挤你或拦你超过 0.5 s 你还不停：+0.7。
- 停车接受罚款：−1。
- 每秒自然下降 0.04。
- 星级越高：
  - 同时出动的警车越多（每星 +1）。
  - 下一辆来得越快（间隔 ÷ (1 + 0.6 × 热度)）。
  - 反应越快，挤得越狠。
  - 2 星起挤你时不再管路肩上有没有车，可能把你挤进车里。

**罚款（`PATROL.fine/fineStar`）**：停车被放行要交 $30 + 每星 $20，弹出 `FINED $X · MOVE ALONG`。结算里单列一行，从奖金里扣。所以要么停车交钱，要么跑，跑就会升星、被挤进车流。

**其他改动**
- 从后方刷出的警车会找一条没有车的车道出来，都不空就等 1 s。原来会刷在车上。
- 结算多两行：打进车流/撞墙、罚款。
- `earned = max(0, 名次奖金 + KO + 报仇 + 打进车流 − 罚款)`。

**实测**（40 局，`npx tsx scripts/bot.ts 40 1 race 3 [stop]`、`fight 0`）

| 竞速：玩家被打 / 摔车 | 12.7 / — | 9.0 / 4.5 |

### 3.3.11 宿敌和激励广告（2026-11-09，SIM_VERSION 13）

**宿敌（`career.ts` 的 feud，存档里 `save.feud`）**
- 每个对手对玩家有一个"仇恨值" beef。每局结算：把玩家打下车一次 +2，比玩家先到终点 +1，被玩家打下车一次 −1，最低 0。
- 没有宿敌时，beef 最高且 ≥ 6 的那个成为宿敌，beef 清零。结算页出现 `☠ NEW NEMESIS` 卡片。
- 宿敌在模拟里（`World.nemesis`）：
  - 极速 +0.6 m/s，攻击性 +0.2，血量 +2（`C.NEMESIS`）。
  - 每局一开始就像记仇一样追着玩家打（`hates(id)`），不会再被记成普通仇人。
- 奖励：每把宿敌打下车一次 $150，比它先到终点 $100，都乘本级奖金倍率。打中时闪 `REVENGE! +$…`。
- 击溃：同一局里**既把宿敌打下车、又比它先到终点**，才算赢它一次。赢满 3 次（`BREAK_AT`）击溃，额外 $500，结算页 `☠ X is BROKEN`。之后由别人的 beef 产生下一个宿敌。
- 为什么不按打下车次数算：实测玩家每局能打下宿敌 2.5–3 次，按次数算 1–2 局就击溃，宿敌不成气候。现在的规则大约 4–5 局击溃，正好跨一个杯赛。
- 比赛开始时倒计时下方显示宿敌卡：名字、它打下过你几次、已赢几次（`beaten n/3`）、每次的赏金。名牌带 ☠。

**平台层（`src/platform.ts`，Playgama Bridge v2）**
- `index.html` 第一个脚本加载 Bridge；`public/playgama-bridge-config.json` 定义广告位：插屏 `race_end`，激励 `double_cash`、`remount`（后来加了 `streak_double`），排行榜 `takedowns`（见 3.3.14）。
- `boot()` 先 `initPlatform()`，再从 Bridge 存储读存档（键 `save`；读不到时迁移旧的 localStorage `dummy-brawl-v1`），全部就绪后 `game_ready`。
- 生命周期：开赛 `level_started`；前 3 名结束 `level_completed`，否则 `level_failed`。
- 平台暂停（`PAUSE_STATE_CHANGED`）停住模拟和声音，和玩家自己的暂停分开；`AUDIO_STATE_CHANGED` 控制静音。
- 激励广告只在收到 `rewarded` 状态时发奖；`closed` / `failed` 不发。120 s 超时保护。
- 本地开发（平台 `mock`）用假广告：遮罩 1.2 s 后算看完。`?noads` 关掉，`?fakeads` 在构建版里打开。

**激励广告两处**
- 结算页 `▶ Double it`：本局所得再加一份，结算表多一行 `Ad bonus ×2`。每局一次。

**保安班**（反向玩法，SIM_VERSION 19，`src/sim/chase.ts`、`src/shift.ts`、`C.CHASE`）：
- 原来 2.4 写的是“后期可以加一个反向模式，但不做主线”，现在做了，作为支线。
- 跑完 3 局后，标题卡和结算页出现“保安班”按钮。

### 3.3.15 第四轮：趣味性（2026-11-10，SIM_VERSION 20）

目标：让一局里“好笑的瞬间”更多、更值得回看，并给杯赛之外加一种短平快的玩法。数值集中在 `src/sim/fun.ts`，逻辑在 `src/sim/stunts.ts`、`src/sim/hazards.ts`、`src/sim/launch.ts`。

**保龄球**（`BOWL`）：
- 玩家摔下车、身体还在翻滚（速度 ≥ 4 m/s）时，左右键能把身体往旁边带（3.2 m/s）。
- 撞上还在车上的骑手就把他撞下来，算一次击倒，额外付 40。每摔一次最多 3 个。

**油桶**（`OIL`，新武器）：
- 不挥向任何人，用出去在身后 2.5 m 倒一滩油，持续 30 s。
- 谁骑过去谁摔，击倒记在倒油的人头上。倒油的人自己有 2 s 豁免。

**每个级别一种路面危险**（`HAZARD`，用比赛自己的随机流放置，不影响车流、AI 和攻击）：
- 草地：牛在路上慢慢来回走，撞上就摔。AI 看得见会绕。
- 沙漠：风滚草横穿马路，撞到把人推开，然后碎掉，3 s 后再出现。
- 秋天落叶、雪地结冰：一段 26–32 m 的滑路，转向抓地力降到 0.45 / 0.3，侧推滑得更远。
- 黄昏：护栏边爆开的消防栓，周期性往路中间喷 6.5 m 的水，把人推开。
- 都避开跳台的助跑和落地区。三角波代替 sin，保证确定性。

**嘲讽**（`TAUNT`）：
- 玩家打倒一个人后 1 s 内能按嘲讽键（HUD 上出现按钮）：付 30，代价是这一下速度降到 0.86。

**杯赛 Boss**（`BOSS`）：
- 每个杯赛最后一局，一个对手变成 Boss：戴王冠、体型更大、更快更凶，多 2 点血，每次挨打只掉 1 点（满蓄力重拳掉 2），被推开的距离减半。
- 第一次放倒它付 300 × 级别奖金倍率。HUD 上它的名牌有 Boss 标记。

**每周变异**（`MUTATORS`，按 UTC 周一起算轮换）：
- 只在每个杯赛的第 2 局生效，奖金 ×1.25。五种：低重力（跳台滞空 ×2）、全员球棒、大头、车流 ×1.6、警车 ×2。
- 开局横幅和结算的奖金行写出这周的变异名。

**精彩回放**（`src/highlight.ts`，`HIGHLIGHT`）：
- 比赛中给玩家的瞬间打分（击倒，打宿敌、满蓄力加分；跳台踩人；保龄球；放倒 Boss；把人推进车流；自己摔得漂亮也算），记住最好的那一刻。
- 冲线后，分数够（≥ 3）就从回放数据重新模拟：先快速、不渲染地跑到那一刻前 40 tick，再用路边机位半速播放 75 tick。点一下或按键跳过。
- 不另存录像：同一种子 + 玩家输入就能精确重现，所以只靠已有的 `Recorder`。
- 机器人模式不播。发 `highlight {skipped}`。

**假人帽子**（`HATS`，`src/view/hats.ts`）：

### 3.3.18 draw call 合并：骑手和布娃娃各一个蒙皮网格（2026-11-10，不动模拟）

**问题**：3.3.17 的复测里，峰值 93 次 draw call 中骑手占 29、布娃娃占 26。
- 原因：每个骑手有 5 个网格（车、腿、躯干、两条手臂），每个布娃娃有躯干、头、四肢和三颗晕眩星星，各占一次 draw call。

**做法：刚性蒙皮**（`toon.ts` 的 `rigidParts` / `rigidMesh`）：
- 把一个角色的所有零件合并成一个几何体。每个顶点只跟一根骨骼，权重 1（`skinIndex` 和 `skinWeight` 用 Uint8）。
- 骨骼就是原来那些零件的 Object3D，动画代码不用改：还是设它们的位置、旋转和缩放。
- `boneInverses` 和 `bindMatrix` 都是单位矩阵。
- 每个角色仍然有自己的材质，受击闪白（emissive）照旧。
- 隐藏单个零件不能再用 `visible`，改成把那根骨骼缩放到 0：
  - 布娃娃的晕眩星星。
  - 骑手摔车后的人。
- 视锥剔除：three 只给蒙皮网格算一次包围球，所以自己给一个，每帧跟着走。
  - 骑手：球心在车身中间，半径取零件最远的点。
  - 布娃娃：球心跟着骨盆，半径 2.4，戴帽子时按缩放放大。
- 释放：场景和弹射模式的 `dispose()` 现在也释放 `Skeleton`（它有一张骨骼纹理）。
- 着色器预热会编译蒙皮变体，着色器程序数没变（19）。

**实测**（Dust Bowl，bot 跑一局，每 40 ms 采样，25 s）：

| | draw call 峰值 | 骑手 | 布娃娃 | 赛道 | 车流 | 三角面 |
|---|---|---|---|---|---|---|
| 合并前 | 93 | 29 | 26 | 25 | 5 | 约 8 万 |
| 合并后 | 47 | 10 | 每个 1 | 25 | 5 | 7.7–8 万 |

- 渲染耗时：中位 0.7 ms，p95 1.4 ms。JS 每帧：中位 0.8 ms，p99 1.5 ms，最慢 1.9 ms（开发机）。
- 跨局内存：上一局结束时 24 张纹理、111 个几何体，下一局开始 3 s 后是 12 和 57，旧骨骼都释放了。
- 浏览器检查过：
  - 骑手完整，带手臂。
  - 布娃娃的身体和四肢完整。
  - 摔倒后车上不再显示人。
  - 弹射模式的假人有晕眩星星。
  - 屏幕外跑回车上的布娃娃没有被错误剔除。
- 现在 draw call 离预算 100 有一半的余量，下一轮可以放心往屏幕上加东西。赛道切片（25 次）以后需要的话再合进 InstancedMesh。
- 真机没有测。手机上用 `?stats` 看帧率和最慢一帧。

### 3.3.20 第五轮打磨 · 性能：正式构建真机实测和矩阵遍历（2026-11-11，不动模拟）

**正式构建的实测基线**（`?bot&len=400`，90 秒，含两次赛间切换）：
- 首次绘制 192 ms，`domInteractive` 105 ms，**1.0 s 可玩**（预热完第一帧）。着色器程序 18 个。
- 整段 5320 帧 / 90.2 s = 59.0 fps。超过 30 ms 的帧一共 22 个：启动占 3 个（933 + 167 + 83 ms，都在加载画面里，玩家还没开始），其余 19 个全是 33–50 ms，也就是掉 1–2 帧。
- **赛间切换不卡**：结算弹出和下一局开跑各只有 33–50 ms 一帧。之前怀疑 `newRace()` 同步重建 `Track` 会卡，实测不成立。
- 启动那 933 ms 里的大头是原生 `(program)`（Mali 编译 18 个着色器），开发构建里额外的 ~300 ms 读着色器日志在正式构建里确实没有了。

**压到 4 倍 CPU 节流再量**（CDP `Emulation.setCPUThrottlingRate`，模拟更弱的机器）：画质分档自己掉到 q3，**仍然 60 fps，中位 16.7 ms，p95 16.8 ms**。分档器是管用的。节流下的 JS 自耗时排名第一档是 three 的场景图矩阵：`updateMatrix` 710 ms + `updateMatrixWorld` 676 ms + `multiplyMatrices` 323 ms（20 秒里）。场景一共 379 个节点，全部开着 `matrixAutoUpdate`。

**改了三处，都只省无用功，不改画面**：
- **赛道建完就冻结**（`Track` 构造函数末尾）。赛道里没有任何东西会再动——锥桶被撞倒是写实例矩阵，不是移动网格。所以每个部件 `updateMatrix()` 一次之后把 `matrixAutoUpdate` 和 `matrixWorldAutoUpdate` 都关掉，渲染器每帧就不再走这一大片子树。`group` 自己保持活的，万一以后要移动，three 的 force 标志仍然能传进去。
- **藏起来的骑手和布娃娃退出矩阵遍历**。`visible = false` 在 three 里不跳过矩阵计算。现在把 `matrixWorldAutoUpdate` 跟着 `visible` 一起设：等着上场的暴徒、起身无敌闪烁的那几帧、收起来的布娃娃（每具 14 根骨头），都不再每帧算矩阵；重新出现的那一帧自动接回来。
- **HUD 两处每帧白写**。进度条的 `fill.style.transform` 原来无条件每帧写一次；现在按千分之一的步长比对，不变就不写。对手名牌的 `translate` 原来每帧 `toFixed(1)` 拼字符串写一遍，现在按十分之一像素比对，位置没动就不写（画面完全一样，`toFixed` 也省了）。

4 倍节流下复测：`updateMatrix` 从自耗时榜上消失，矩阵三项合计 1709 → 1307 ms（-24%）。帧率本来就顶到 60，省下来的是余量，给更弱的机器。手机上逐帧看过一局：赛道、护栏、树、路牌、骑手名牌、HUD 全部正常。

### 3.3.21 第六轮打磨 · 玩法：一局的长度，和手机上读得清的 HUD（2026-11-11，SIM_VERSION 22）

**一局太长了。** 1.2 和 3.1 写的目标是一局 120–180 秒，实测超了。`npm run bot` 的平均完赛时间（Amateur 档）：div 0 无升级 180 s、div 1 167 s、div 2 162 s、div 3 172 s、div 4 168 s。Pro 档再乘 1.12、Legend 档乘 1.18，也就是正常生涯里一局 160–195 秒，上限整个压在目标带的外面。这是面向 Playgama 的手机网页游戏，一局三分钟太久。

`RACE_LEN` 3800 → **3400**（-10.5%），`SIM_VERSION` 21 → 22（`world.test.ts` 的金哈希跟着换成 `3476398f` / `e7c7c0a0` / 4883 tick）。模拟里所有节奏点都是按 `w.length` 的比例算的（巡逻起点、车流密度、武器刷新、威胁生成），所以缩短是整条弧线一起缩，不是砍掉结尾。复测：Amateur 档 149–162 s，Pro 约 167–175 s，Legend 约 176 s 封顶——全部落回 120–180 内。开局的承诺没变（`scripts/first20.ts`：第一次看到打斗中位 2.5 s，第一次有人被打下车 3.8 s，玩家第一次挨打 11.2 s，第一次摔 15.0 s），缩的是尾巴不是头。

**HUD 顶栏在 384 px 宽的手机上溢出。** 真机量出来：通缉星星一出现，顶栏的弹性空隙 `.grow` 被压成 0 宽，暂停键右边缘跑到 393 px，而视口只有 384——暂停键被屏幕边切掉，喇叭键压在钱箱上面（`t4.png` 里钱显示成「$9,7」）。顶栏里排着名次、血点、通缉星、钱、喇叭、暂停，手机宽度装不下。把**通缉星星从顶栏挪到进度条下面、靠左**（`.heat` 改成绝对定位，横屏下再上提 10 px），顶栏的空隙 `gap` 10 → 8 px。复测：暂停键 328–372，正好停在 384-12 的安全边里，空隙还剩 28 px，360 px 的窄机也装得下。

**对手名牌叠在一起看不清。** 两个骑手并排时，两张名牌画在各自头顶，字叠字（`t2.png` 里「Sticker」被「Nugget」盖掉一半，只剩「Sti…er」）。现在每帧按骑手顺序摆牌：要落的位置和已经摆好的牌重叠，就往上抬一行（20 px），最多抬三次。按骑手下标而不是按远近排序，是为了两人互相超越时名牌不会来回跳。牌宽在每局开赛时量一次存起来（图标类名另加 15 px），每帧不再读布局。真机 600 帧采样：**重叠帧 0**；四张牌同屏时整齐地叠成一列。

### 3.4 着色器预热和画质分档（2026-11-10 落地）

- **预热**：`RaceView.prewarm()` 先把所有纹理传上 GPU，再 `compileAsync`（没有就 `compile`），最多等 4 s；超时就先放行，剩下的后台编完。three r186 的 `compile()` 会遍历隐藏物体，所以不用切可见性。拾取环放了一个隐藏的 `proto`，保证它的着色器也被编到。`game_ready` 在预热完、第一帧画上屏之后才发（两次 rAF）。之后每局在构造时同步 `compile` 一次，材质是跨局共享的，基本不花时间。
- **释放**：上一局的几何体和材质用 `stage.retire()` 排队，等新一局画完第一帧再释放。先释放会把着色器程序删掉，下一局又得重编。材质、骑手、布娃娃、车辆、粒子的几何体都跨局缓存（`toon.ts` 的 `cached()` / `shared()`），粒子用固定 160 个的池。
- **分档**：`src/view/quality.ts`，6 档，主要是像素比上限 0.5 / 0.75 / 1 / 1.25 / 1.5 / 2，最低两档粒子减半。低于 40 fps 持续 3 s 降一档，3 s 平均低于 15 fps 直接降到底；高于 57 fps 30 s 才升，每局最多升一次，升了守不住 54 fps 就退回并锁定。在这块屏幕上看起来一样的档（像素比上限高于屏幕本身）直接跳过。
- MSAA 只能在建上下文时定：触屏设备和软件 GL（SwiftShader、llvmpipe）关掉；软件 GL 从最低档开始。
- 玩家可在暂停菜单选 自动 / 低 / 高，存进存档；`?quality=` 参数强制档位，优先于两者。档位变化发 `quality_changed {tier, prev, mode}`，每个事件带公共字段 `gfx`（当前档）。
- 视距：每档还带一个视距系数 0.6 / 0.75 / 0.9 / 1 / 1 / 1，乘到场景的雾近、雾远上，相机远平面跟着放在雾远 + 10 m。路面、地面、护栏、树按 150 m 一段切开（`Track.strips` / `Track.sliced`，护栏和树每段一个 InstancedMesh），视锥和远平面才能把看不见的段整段丢掉。实测起跑线：最低档 7.3 万三角形（切段前全程整块画，约 15 万），最高档 7.7 万，draw call 67–74。
- 开发服务器默认锁最高档（见 3.3.14）。没做：iOS 低电量 30 fps 的特殊处理（降档器自己会降）。
- 没有 WebGL（`new Stage` 抛错）显示一张"浏览器不支持"的卡片和重新加载按钮，发 `error_report {kind: no_webgl}`；上下文丢失时暂停并显示提示，恢复后自动消失。

### 3.5 HUD

Swarm Orbit 在 Galaxy A16 上的瓶颈不是 WebGL，是 DOM HUD 重绘：

- 每个会变的 HUD 块单独 `will-change: transform`。
- 进度条、速度表用 `transform: scaleX`，不改 `width`；不做 filter 动画。
- 名次、速度、生命这类每帧都变的数字，考虑直接画进 WebGL（字形图集），不走 DOM。

**时速表**（左下角，`hud.ts` 的 `.speedo`）：

- 显示玩家时速：`speed × 3.6`，取整，单位用各语言的 `kmh`。
- 每 0.12 s 才写一次文字，只在数字变了时写。数字用游戏数字字体的等宽数位（见下面的「数字字体」），盒子加 `contain: layout`，不会牵动别的 HUD 重排。A16 上没测到额外开销，所以没改画进 WebGL。
- 超过车的极速 0.5 m/s 以上（跳台加速，最多 ×1.15）时数字变黄。下车时显示 0。
- 开局的操作提示条和它在手机上会重叠约 14 px，所以提示条出现时它先淡出（`#hud.hinting`）。
- 实测基础车巡航 95 km/h，跳台加速到 109 km/h。

**数字字体**（`style.css` 顶部的 `@font-face`）：

- HUD 上所有数字原来跟着系统字体走，每台设备长得不一样：Windows 上是 Segoe UI，安卓上是 Roboto，iOS 上是 SF。名次、钱、时速、倒计时、KO 弹字、追兵米数、结算卡的十几行金额，粗细和宽度都对不上。
- 现在统一成 **Baloo 2 ExtraBold**（SIL OFL 1.1，可嵌入、可再发布；授权全文在 `src/assets/digits-baloo2.LICENSE.txt`）。圆头粗体，跟场景的卡通描边是一路的。
- 机制只有一条 CSS：`@font-face` 带 `unicode-range: U+24-25, U+2b-2c, U+2e-3a, U+d7, U+2212`（`$ % + , . / 0-9 : × −`），然后把这个字体名放在 `--font` 的最前面。浏览器只从它取这几个码位，字母全部仍从系统字体取。所以**一行 HTML 都没改，一条翻译都没动**，俄语、土耳其语的词还是系统字形、原来的宽度，不会溢出。结算卡在俄语下逐行核过，没有一行撑破。
- 子集只有 **4196 字节**（Google Fonts 的 `css2?...&text=` 直接给已切好的 woff2；要用桌面 Chrome 的 UA，否则给的是 ttf，命令写在 `style.css` 的注释里）。源文件留在 `src/assets/digits-baloo2.woff2`，CSS 里是它的 base64 内联副本。
- 为什么内联成 `data:font/woff2`：没有请求、没有 swap、第一帧就是最终字形，dev 和构建后完全一样（手机上连 dev server 测出来的结论才算数）。`font-display: block` 只是兜底。`font-weight: 1 1000` 让这一个字重应付所有字重，不会被合成加粗。
- 代价：CSS 从 21.6 kB / 5.3 kB(gzip) 变成 27.4 kB / 10.1 kB(gzip)，多 4.9 kB(gzip)。JS 包不受影响（240 kB gzip，预算 260）。
- 附带修好一个哑弹：时速表上的 `font-variant-numeric: tabular-nums` 以前是空转的 —— Segoe UI 没有 `tnum` 表。Baloo 2 有，所以数字现在真的等宽（0-9 都是 24.25 px），`min-width` 从 2.1ch 提到 3.1ch，0–999 全程 `km/h` 不再左右跳。
- A16 实测（Android 15 Chrome，dpr 2.8125，384×671 CSS px，`?bot` 跑同一段赛道）：字体在导航后 **68 ms** 就可用，首帧绘制在 **128 ms**，字体比第一个像素早到 60 ms —— 第一帧就是最终字形，没有闪烁也没有回流。帧率对照（同一局中段取 5 s）：系统字体 60.0 fps / 中位 16.7 ms / p95 17.8 ms，换成数字字体 60.2 fps / 中位 16.7 ms / p95 17.9 ms，噪声范围内一致，没有下降。俄语结算卡在 384 px 宽下也逐行核过，最长的一行「Серии нокаутов (лучшая 3×)」离右边的金额还有余量。
- 不做的：按数字切图或在代码里画 SVG 数字。数字是插在翻译句子里的（`KO! +${n}`、`гонка {n}/{m}`），拆不出来；而且图片数字没法用 CSS 换色（白 / 黄 / 红），在 dpr 2.81 上还会糊。

#### 3.7.3 门户 iframe 的键盘焦点（2026-11-10，照 Holy Kicker 的做法，不动模拟）

游戏在门户页的 iframe 里时，iframe 拿到焦点之前，按键都发给门户页。方向键和空格会滚动门户页，游戏却收不到。Playgama Bridge 还会在游戏窗口失焦时发 `pause_state_changed`，于是游戏停住、没声音，看起来像卡死。

- 要焦点（`src/view/input.ts`）：
  - 开机时调一次 `window.focus()`。跨源 iframe 在没有用户手势时，这一下通常不生效。
  - 每次指针按下（捕获阶段，按钮也算）再调一次。
- 不滚动：`ArrowUp/Down/Left/Right` 和空格的 keydown、keyup 都 `preventDefault`。
- 提示：
  - 触发条件：桌面（`(pointer: fine)`），比赛中，没暂停，且 `document.hasFocus()` 为假（`keysReach()`）。
  - 表现：底部那条提示换成黄底、带脉冲的“点击游戏以使用按键”（`clickForKeys`，7 种语言）。
  - 在 `frame()` 判断主机暂停之前就更新，所以 Bridge 暂停时也能看到。
- 倒计时等焦点：条件同上，倒计时还没走完就不推进模拟，免得比赛在键盘不能用时开跑。
  - 主要是新玩家自动开跑的第一局会碰到。后面的比赛都要点按钮才开始，点按钮本身就把焦点给了游戏。
  - 等到焦点后发 `keys_wait`。
- 手机、平板不受影响。
- 测试页：`dev/portal.html`，不进构建。
  - 启动配置 `portal` 在 5181 端口起同一个项目，作为另一个源；页面把游戏（5180）放进 iframe，地址栏的查询参数原样传给游戏。
  - 用 headless Chrome 测过：门户输入框持有焦点时，游戏显示提示、倒计时停住、宿主处于暂停。点游戏后，焦点进游戏、暂停解除、倒计时继续；之后方向键和空格不再滚动门户页。

#### 3.7.4 更全的数据（2026-11-10，照 Playgama 遥测指南和 Holy Kicker、fang、jump 的做法，不动模拟）

要求是尽量多收数据。所以加了下面这些，每个事件都对应一个具体问题，所有值都有界：数字、布尔，或固定的几个词。不发报错信息、URL、堆栈、名字，也不自造 session_id。会话、时长、广告展示和购买由 Bridge 统计，这里不重复。

代码分布：
- `src/metrics.ts`：纯逻辑，有测试（`metrics.test.ts`）。
  - `PerfSampler`、`RunStutter`
  - 生涯分档、step_id、设备
- `src/telemetry.ts`：接到游戏上。
- `main.ts`：只有十几行挂钩。
- 构建版本：`vite.config.ts` 把 `package.json` 的 version 注入成 `__BUILD__`，现在是 0.2.0。

**每个事件都带的公共字段**（`platform.setCommonFields`）：

| 字段 | 值 |
|---|---|
| `device` | ios / android / desktop / other |
| `form` | Bridge 的设备类型 |
| `touch` | 是否触屏 |
| `orient` | land / port |
| `lang` | 界面语言 |
| `build` | 构建版本 |
| `new_player` | 是否第一次会话 |
| `career` | 生涯局数分档：0 / 1-4 / 5-19 / 20-49 / 50-99 / 100+ |
| `rung` | 梯子上的位置，0–14 |
| `session_n` | 第几次会话，封顶 20 |
| `days` | 距第一次会话的天数，封顶 30 |
| `focus` | 游戏是否有键盘焦点 |

- `sessions` 和 `firstDay` 存在存档里。
- Bridge 起来之前的事件（启动报错之类）先排队，最多 40 条，读完存档后一起发出去。

**`performance_sample`**（指南的契约）：
- 统计范围：只算看得见、没暂停的比赛帧（不算机器人）。
- 发送时机：
  - 每满 30 s 发一次。
  - 比赛结束、暂停、主机暂停、页面隐藏时，把攒下的发出去，但不足 5 s 的丢弃。
- 帧的处理：
  - 帧长取 clamp 之前的真实值。
  - ≥5 s 的帧视为间隔，不算。
  - 离开后回来的第一帧不算。
- 必填字段全有。
- 可选字段：
  - 长任务数、总时长、最长
  - JS 堆（`memory_measurement_type: js_heap`）
  - 本窗口的 JS 错误、未处理拒绝、WebGL 丢失、音频加载失败次数
- 另加 `dpr`、`mpix`（画布百万像素）、`step_id`、`racers`。

**进度**：

| 事件 | 时机 / 字段 |
|---|---|
| `progression_started` | 每局开始。`step_id`、`step_index`、`tier`、`div`、`cup_race`、`ride`、`career_race`、`cash`、`up_total`、`nemesis`，以及上一局结算页停了几秒（`results_sec`）、买了几样（`buys`） |
| `progression_completed` / `progression_failed{reason: place}` | 每局结束。前 3 名算完成，与 `level_completed` 一致。字段：名次、人数、KO、宿怨 KO、推人、罚款、摔车次数和按原因分的 `falls_ko/car/wall/cones`、倒地秒数、用时、是否到了时间上限（`capped`）、主要输入方式（`input`：key / mouse / touch / none）、暂停次数、切走次数、复仇数、本局挣的钱、余额、升级总级数，以及本局卡顿（`run_*`，含最长一帧出现在第几秒 `run_frame_max_at_s`） |
| `progression_failed{reason: abandon}` | 比赛中关页面。带当时的局面，`started` 表示是否已过倒计时 |
| `cup_completed` | 杯赛结束：`rank`、`promoted`、`champion`、`next_tier`、`bonus` |
| `division_reached` | 升级到下一个赛区 |
| `title_won` | 夺冠 |
| `season_reached` | 进入下一赛季 |
| `ride_unlocked` | 新坐骑解锁，带买不买得起 |
| `nemesis{result}` | 宿敌：`new` 新宿敌、`beaten` 击败一次、`broken` 彻底打垮 |

- `step_id` 是赛季加赛区，比如 `amateur_rookie_meadow`，共 15 个。
- `step_index` = 梯子位置 × 4 + 杯赛第几场，取值 1–60。

**广告漏斗**：
- `ad_offer{placement}`：
  - 结算页出现翻倍按钮时发一次。
  - 比赛中第一次出现"马上骑回去"时发一次。
- `ad_result{placement, result, sec}`：在 `platform.showRewarded` 里发。`result` 是 rewarded / closed / failed / timeout / unavailable 之一。

**报错**：
- 事件：`error_report{kind, screen, stage, n}`。
- `kind` 的取值：
  - js_error
  - unhandled_rejection
  - webgl_lost
  - stall：比赛中 1–5 s 的帧，带 `ms`，取整到 100
  - boot_fail
  - boot_slow：20 s 还没起来
- 每种每个会话最多 3 条。

**启动**：
- `game_loaded` 带 `script_ms`、`bridge_ms`、`save_ms`、`ready_ms`，都从页面开始加载算起。老的 `ms` 从漏斗模块启动算起，和前三个不在一个基准上，保留只为兼容。
- 起来之前就离开的，发 `boot_left{stage, ms}`。这条只有在 Bridge 已经起来时才发得出去。

**离开**：`session_end` 带 `cash`（没花的钱）。
- 在结算页离开：加 `can_buy`，表示有升级买得起却没买。
- 在比赛中离开：加 `step_id`、`race_t`、`place`、`down`、`started`。

**发呆**：`idle{screen, sec}`。
- 阈值：比赛 30 s（原来 15 s，见 3.7.5）、结算 45 s、标题 30 s。
- 输入包括指针移动、按键、滚轮、触摸。
- 每次进入一个界面最多发一次，每个会话最多 5 次。

**经济**：
- `upgrade_purchased` 带 `price` 和 `cash`。
- `ride_chosen` 带 `price` 和 `cash`。

**删掉的**：`early_race`。`progression_*` 加上 `career_race` 已经包含它。

**验证**：用 headless Chrome 加 `?trace` 跑了三个场景。
1. 新玩家两局：
   - 有教程步骤、`progression_*`、`ad_offer double_cash`。
   - 每 30 s 一条 `performance_sample`。
2. 老玩家：
   - 点了"马上骑回去" → `ad_offer remount` + `ad_result rewarded`。
   - 按 P 暂停 → `pauses: 1`。
   - 15 s 不碰 → `idle`。
   - 关页面 → `session_end` 带比赛局面，加 `progression_failed{abandon}`。
3. 杯赛最后一场：
   - `cup_completed` → `division_reached` → `ride_unlocked`。
   - 手动抛的错和拒绝各发了一条 `error_report`。

### 3.7.1 暂停菜单、每日挑战、回归玩家标题页、存档安全（2026-11-10）

**暂停菜单**（`src/view/menu.ts`）：继续、音乐开关、音效开关、震动开关（只在能震的设备上显示）、画质（自动/低/高循环）、玩法说明、重开本局。设置都进存档（`musicOff`、`sfxOff`、`hapticsOff`、`quality`），改动发 `settings_changed`。重开算一次失败：`progression_failed {reason: restart}`，并走一次 `restart` 插屏位。

**每日挑战**（`src/daily.ts`）：
- 每天按日期哈希出 3 个不同的挑战，从 7 种里选：击倒 6 次、打进车流 3 次、前三 2 次、赢 2 次、跑完 3 局、不摔跑完 1 局、报仇 2 次。
- 每个完成付 250，当天第一次赢付 400，都乘当前级别的奖金倍率；只付一次。
- 结果页显示三项进度，刚完成的高亮；完成发 `daily_done {kind, done}`，首胜发 `first_win {cash}`。
- 存档里坏掉的 / 过期的每日数据按新的一天重置。

**回归玩家标题页**（`src/view/title.ts`）：打过至少一局的玩家，标题卡下面显示下一台车（还差多少钱 / 可以买了 / 哪个级别解锁）、宿敌和被打败次数、今天的挑战和首胜奖励。新玩家仍然直接进第一局，不显示菜单。

**存档安全**：
- `loadData()` 带重试和超时，返回 `{ok, data}`。读失败时本次会话用新存档玩，但**不写回**（`writable = false`），免得把玩家的生涯覆盖掉；屏幕上提示一次，发 `error_report {kind: save_read}`。
- 写入排队，同一时刻只有一个写在路上，后来的覆盖排队中的。

**其他修正**：
- 复活广告改成 `click` 触发，按钮出现 350 ms 后才生效（防止转向的手指误触）；广告等待期间模拟暂停；广告失败或玩家已经站起来，就不扣这局的次数。
- 结果页出现 600 ms 内的点击和按键不算；回车 / 空格在标题页开始、在结果页继续。
- 音频解锁监听 pointerdown / pointerup / touchend / click / keydown；音乐缓冲按需淘汰；iOS 的 `interrupted` 状态会恢复。
- 数字用 `Intl` 按语言格式化（`num()` / `money()`），车名、"解锁于"都本地化。
- 按钮 44 px、最小字号 12 px、`touch-action: manipulation`；提示和级别标签在长语言下换行；侧边来车提示避开安全区；覆盖层 `overscroll-behavior: contain`；`prefers-reduced-motion` 下关掉循环动画；危险提示闪烁从约 8 Hz 降到约 3 Hz。
- 启动时检查 `interstitialState`，平台已在播广告就不再请求。

### 3.8 不要做的事

- 不要自己打开 Playgama 沙盒、QA、游戏页（会增加启动次数、拉低平均时长）。
- 不用 PBR 贴图，不用 AI 生成的模型。描边让三角面翻倍，所以按整场预算控制（见 3.3.1），不按单个模型卡 1500 面。
- 不上物理引擎（Rapier/Cannon 的 wasm 就要 1–2 MB，而且破坏模拟层的可复现性）。
